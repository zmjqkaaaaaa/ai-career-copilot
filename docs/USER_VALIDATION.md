# AI Career Copilot 真实用户试用计划

计划日期为 2026 年 11 月 22 日。首轮计划招募 5 位成年人，每人约 45 分钟。由项目负责人确定受邀者和试用方式，主持人观察操作，观察员记录任务结果。一人主持时可先记关键时间和求助动作，结束后立即补齐。

11 月 22 日，本地前端和 API 存活检查均返回 200，数据库检查通过，Worker 心跳过期，就绪检查返回 503。Docker 整栈和公网 HTTPS 实测仍待完成。当日可准备材料和演练非 AI 操作。参与者操作的 AI 环节应等隔离预演通过后安排。预演可使用 [上一轮验收场景](PRODUCT_ACCEPTANCE.md) 和 [简历合成样例](../backend/tests/fixtures/resume_cases.json)。现场如遇配额、超时或服务故障，记为环境阻塞。展示事先准备的截图或报告时，注明是演示并记录参与者的理解，相关任务完成指标留空。

## 招募和素材

入组条件是最近 30 天为相关求职实际做过至少一件事，例如整理简历、筛选岗位、做项目或练习面试。每人选一个主要场景，有重叠时保留次要标签。优先通过同学、校友和允许招募的求职社群触达，避免五人来自同一个熟人小组。

| 编号 | 主场景 | 专项任务 |
| --- | --- | --- |
| P01 | 正在投 AI 产品经理岗位 | A2、A6 |
| P02 | 正在投 AI Agent 产品岗位 | A2、A3 |
| P03 | 没有相关实习经历的应届生 | A3、A5 |
| P04 | 有项目，讲不清技术实现的学生 | A4、A3 |
| P05 | 近期准备 AI 产品面试的学生 | A5、A6 |

**邀请文案**　我正在做一个 AI 求职成长工具，想了解你最近一次准备相关岗位的经历，并请你现场试用一段流程。大约 45 分钟，可以用我们准备的示例材料，参与自愿，可随时退出。如果方便，请告诉我最近做过哪类求职准备，以及哪两个时段合适。

主持人准备一份虚构简历、两份带正反例的 JD、一份待理解的公开教学仓库和一条虚构投递。预演时记下标准可核对证据，如简历里真实出现的技能、JD 中缺少证据的要求，以及仓库中的一个关键输入或边界。每次从空账号开始。现场使用参与者自己的公开 JD 或脱敏材料时，另记来源类型，以便和统一样本的结果对照。

**开场说明**　今天测试的是产品。你可以先用示例，随时跳过问题或停止。我们只记编号、操作和经同意的必要摘录。涉及外部 AI 时，页面会显示待发送内容和接收方，请你自行核对后决定是否提交。默认不录音、不录屏。

参与试用、允许录制和允许产品发送内容各自单独确认。研究记录仅保留匿名编号，联系方式保存在独立受控位置。真实素材只接受自愿提供且脱敏的文本，避免姓名、联系方式、证件、私有代码和第三方个人信息。跳过上传和撤回同样记录；用示例继续的参与者单独标记。方案建议原始观察记录和招募映射在本轮结束后 30 天内清理，试用数据和备份的留存须在招募前确认。退出或要求删除时，处理研究记录和产品账号两处。删除功能还需要核实文件清理状态；第三方或历史备份中的副本按已披露的处理与保留方式单独记录。 [现有删除与运行流程](OPERATIONS.md)

## 单场流程和提问

| 时间 | 主持动作 |
| --- | --- |
| 0–5 分钟 | 说明试用范围、退出方式和记录授权。 |
| 5–13 分钟 | 先问上一次相关任务和替代办法，记录具体时间、动作、成本和结果。 |
| 13–38 分钟 | 给出公共任务 A0、A1，再做表中两项专项任务。每项按预设时限记录。剩余任务标为未分配。 |
| 38–45 分钟 | 让参与者复述产品用途和下一步，询问是否愿意选定一个具体的复试时间。 |

可直接使用以下非引导式问题。

1. 上一次准备这类岗位是什么时候？你先做了什么，最后留下了什么？
2. 当时用过哪些工具、资料或别人给的帮助？哪一步花时最多？最后怎么处理的？
3. 最近一次判断自己是否够资格投递时，你依据了什么？哪项判断后来被改掉？
4. 最近一次尝试解释一个项目或练习面试时，有哪个问题你当时答不上来？后来怎么补？
5. 你上一次在哪儿记录投递？后来什么时候打开过，做了什么？
6. 完成试用后，用自己的话说说你刚才得到了什么。哪条输出你会拿去验证？你打算怎么验证？
7. 如果你有一个近期岗位或项目需要继续处理，你愿意选一个时间来复试吗？记录具体任务和时间，允许当场拒绝。

观察任务时先等待，超过约 60 秒无进展，可问「你现在想做什么？」如需指出入口或直接示范，记录发生的时间与具体提示。访谈结束后把亲眼看到的动作、参与者的原话和主持人的推断分开记录。访谈提纲自检为 4/7，当前已覆盖过去行为、具体事实、反证和事实与推断分开。实际跟进承诺、参与者是否主讲、团队是否更新判断，留到首场执行后补分。

## 任务卡

| 编号与用时 | 对参与者说 | 成功证据 |
| --- | --- | --- |
| A0 · 3 分钟 | 建一个试用账号，找到你接下来能做的事。 | 独立注册并登录，能指出首个动作。观察员在结束时听取一句产品用途复述。 |
| A1 · 7 分钟 | 用一份材料看看系统理解了你的哪些能力；你可选择用示例或跳过上传。 | 能解释接收方和发送范围，确认一份已生成画像，并能指出一条原文依据或一处待修正内容。上传选择另记。 |
| A2 · 7 分钟 | 判断这个岗位值不值得继续准备。 | 找到匹配报告，指出一条具体要求、一条证据或证据缺口，并提出下一步。 |
| A3 · 7 分钟 | 找一个能弥补刚才差距的小项目。 | 从候选中选定一项，说明和目标岗位的关系，指出 PRD 的第一项可验证结果。项目采纳需另有后续行动。 |
| A4 · 7 分钟 | 看懂指定函数，用自己的话解释它，再做一道理解题。 | 有保存的测验或掌握记录。用同难度前后题比较解释，0 分为说不清，1 分为能说出作用，2 分为还能说明输入、输出或边界。 |
| A5 · 7 分钟 | 回答一轮模拟面试，从反馈里找到要补的一点。 | 有完成的报告，能指出回答中的不足，并生成或更新一项七天内可执行的学习任务。 |
| A6 · 7 分钟 | 在自己的试用看板中保存一条投递记录，再写下下一步。 | 指定了简历版本，保存投递与下一步，刷新后可找回。七天内主动修改状态或日期另外记录。 |

时间不足时将任务标为未完成或未分配，按实际原因记录。首次理解度用 0–2 记分，0 表示无法描述用途，1 表示能描述单项功能，2 表示能用自己的岗位举例，并说出一个可执行的下一步。A0、A1 单独报告是否独立完成，准确区分注册完成、上传选择、报告完成和理解结果。

## 数据记录和口径

每次任务记录一行，使用本地受控表格即可。字段为参与者编号、任务 ID、开始和结束时间、素材来源、完成状态、提示次数、卡点、可核对的证据或请求 ID、事实摘录、观察员推断。状态使用独立完成、提示后完成、未完成、用户跳过、环境阻塞、未分配。没有观察到的结果留空。每个指标按人去重，保留分子、分母和环境阻塞数。访谈和表格中均不保存简历正文。

```csv
参与者编号,任务ID,开始时间,结束时间,素材来源,完成状态,提示次数,卡点,记录或请求ID,事实摘录,观察员推断
```

| 指标 | 分子 ÷ 分母 | 记录依据 |
| --- | --- | --- |
| 注册完成率 | 从登录成功进入产品的人 ÷ 开始 A0 的人 | 观察及登录成功画面 |
| 简历上传完成率 | 上传成功并进入解析的人 ÷ 开始上传操作的人 | 上传状态。另记愿意用自有脱敏材料、用示例或跳过 |
| 职业画像生成率 | 生成可读画像的人 ÷ 提交生成的人 | 生成结果和确认状态分开记 |
| 岗位匹配使用率 | 打开一份已生成匹配报告的人 ÷ 已开始 A2 的人 | 报告页或可核对记录 |
| 项目推荐采纳率 | 选定方案且另有一次后续动作的人 ÷ 看过推荐结果的人 | PRD 新版本、关联仓库或具体里程碑之一 |
| 代码教学完成率 | 完成解释与测验的人 ÷ 开始 A4 的人 | 教学记录、测验与前后题结果 |
| 模拟面试完成率 | 生成并查看报告的人 ÷ 开始作答的人 | 报告与复述的薄弱项 |
| 学习任务完成率 | 截止前完成所选学习任务的人 ÷ 已选任务且截止日已到的人 | 成长中心完成状态和可选产出核对 |
| 投递记录创建率 | 保存至少一条有效内部记录的人 ÷ 开始 A6 的人 | 记录 ID 与刷新后的内容，使用试用岗位 |
| 七日留存率 | 注册后第 168 至 192 小时内至少完成一次主动业务动作的人 ÷ 已达到 192 小时且参加独立试用的人 | 再匹配、完成任务、继续面试、创建或更新投递等；开始时间统一从注册记 |

若缺少七日窗口行为观测，标记为未知并单列人数。仅在观测完整时给出正式留存计数。有人撤回的数据按约定移除并说明分母变化；未到观察窗口的人单列为未成熟。首次有主持的任务不能计为七日主动回访。默认用原始业务记录与匿名观察表核对，现阶段没有试用分析埋点。

## 决策与复报

- 先看是否至少 4/5 能独立完成公共入口 A0，并且至少 3/5 能基于输出说出一个带证据的下一步。环境阻塞单列，并补测被阻塞的人。这两个数字是本轮建议门槛。
- 两人以上在同一处卡住，先修该处并交给新参与者复测。发现跨账号数据、未经确认的数据外发或会误导投递的经历编造，暂停受影响任务，保留不含敏感内容的复现信息。
- 复报每个任务的原始分母、独立完成数、帮助数、退出或阻塞原因。优先写三条足以改变下一轮的发现。每条写明证据、替代解释、应改内容和复验方式。
- 五人结果用于发现问题和挑选下一轮假设。商业信号记录和决策见 [商业化验证方案](COMMERCIAL_VALIDATION.md)。
