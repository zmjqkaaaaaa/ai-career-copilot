# 模拟面试复盘示例 · 公开队列源码

该示例使用公开的 yocto-queue 提交 `72a8fa96a9d389765cdf2bb9c6daba8302fc375d` 和虚构作答。原始模型复盘和训练任务保存在 `work/phase7/live-interview.json`。

## 项目追问

练习题是「移除最后一个元素时，队头和队尾如何变化？」可以先区分调用前空队列、移除单节点和移除多节点队头三种情况。源码在开始时暂存队头，空时返回，非空时前移队头并减少计数。如果前移后队列为空，就清空尾引用并返回原队头的值。下一次入队会依据队头是否为空选择分支。模型提出的影响需要回到实际代码逐条核对。 [对应源码](https://github.com/sindresorhus/yocto-queue/blob/72a8fa96a9d389765cdf2bb9c6daba8302fc375d/index.js#L24-L53)

## 复盘和训练

- 看得见的能力是能描述出队主流程。要练习的是把入队、出队和边界条件串起来。
- 做一张走读表。依次执行入队 A、入队 B、出队两次、再入队 C，逐步写下队头、队尾、长度和返回值。
- 验收自己能指出空队列出队的提前返回、单节点清空尾引用，以及再入队时重新设置头尾的分支。
- 本人陈述与项目证据分开。能解释公开源码可以作为代码走读证据，合成作答未声称参与该仓库开发。

## 评分抽查方式

用同一道 JSON Schema 异常题对比简洁正确、术语堆砌、概念错误和表示不知道四份回答。检查各评分理由是否回答这道题，引用能否回到答案，低证据覆盖时报告是否暂停显示总分。真实模型对照结果保存在 `work/phase7/rubric-calibration.json`。

最终复测中，简洁正确为 70.98 分、覆盖率 74.67%，误把 HTTP 200 当作 Schema 合格的回答为 6.7 分、覆盖率 74.67%。术语堆砌和表示不知道分别只有 37.33% 和 6.67% 的证据覆盖，未展示分数。人工检查仍能看到模型为未展开的重试细节扣分，单一案例可用于调试规则。公开仓库面试回答了两题，覆盖率 43.33%，未给出总体分。
