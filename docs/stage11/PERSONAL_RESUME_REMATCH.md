# 个人实测：用同一份 JD 修改简历并复查

我在准备 AI 产品经理实习时，用自己的简历和一份目标岗位 JD 跑完了「初次匹配 → 核对证据 → 修改简历 → 同岗位复查」。这次还发现了两层问题：有些经历需要在简历里写得更具体，有些内容写清楚后，匹配规则仍识别不到。

## 从看到差距到改完简历

| 步骤 | 我的操作 | 得到的证据或决定 |
| --- | --- | --- |
| 初次匹配 | 用原简历 V0 匹配目标岗位，逐项看报告。 | 报告漏判在读状态、实习时长和作品经历。我回到原文，确认学历日期、可实习月数和项目产出都已写出。 |
| 选择修改项 | 先修复原文已经存在却被漏判的规则，再用报告选出确实值得补写的内容。 | 把工具深度使用、用户体验改进和概念认知作为优先补充项。教育背景继续写真实专业。 |
| 修改并确认 | 第一稿补了项目案例，我发现它还没有逐条回答建议。第二稿 V2 写清了 Codex 的使用频率、负责任务、改进思路和回归用例，并补了自己发现使用问题、邀请同学试用和推动改动的经历。 | 确认自己确实使用过 Agent、Skills 和 Memory 后，把这部分也写进简历。 |
| 第一次复查 | 用同一份 JD 重算 V2，发现两份简历在旧规则 `job-match-v9` 下都得 33.21。 | 报告已经引用 V2，但新增内容没有使判定升级。仅看总分看不出用户做过的修改，也容易让用户误以为建议无用。 |
| 修复后复查 | 与 Codex 协作，把新增证据对应到明确的判定规则和回归用例，再回到产品中用同一份 JD 匹配 V2。 | 页面保存了新版报告。可以看见哪些条件因证据变得明确，哪些仍需要面试举例。 |

## 用同一套规则比较

使用同一 JD 和同一评分规则 `job-match-v10`。V0 从保存的原简历在本地重建，V2 为我在页面实际发起并保存的报告。

| 结果 | V0 原简历 · 本地复算 | V2 修改后 · 页面结果 |
| --- | ---: | ---: |
| 证据支持分 | 33.21 / 100 | 76.09 / 100 |
| 证据覆盖率 | 55.83% | 97.50% |

| JD 条款 | V0 | V2 的新增证据 |
| --- | --- | --- |
| 高频使用 AI Agent 类工具，能说明改进思路 | 部分符合 | 达到简历证据要求。提供了使用频率、实际任务和把漏判写成回归用例的改进实例。 |
| 从实际使用场景发现体验问题并提出改进 | 待核实 | 达到简历证据要求。说明了本人在哪一步卡住，以及如何把预览、确认和结果放在同一区域。 |
| 自驱力与学习能力 | 待面试核实 | 部分符合。主动邀请试用和跟进改动提供了行为证据，仍可在面试中补充细节。 |
| 对 Agent、Skills、Memory 有基础认知 | 待核实 | 达到简历证据要求。添加了本人确认过的使用经历。 |

新版总分增加 42.88 分，覆盖率增加 41.67 个百分点。分数变化反映这份 JD 下简历证据更容易被识别，并记录了匹配规则的修复过程。样本为项目负责人单次自测，范围到重新匹配并拿到报告为止。实际投递、面试邀约、录用结果及其他用户能否独立完成流程，仍需各自验证。
