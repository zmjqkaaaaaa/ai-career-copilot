# Badcase 分析 · 简历与岗位匹配

我用失败案例检查三个环节：原文是否读到了、证据是否归类正确、评分有没有反映用户的实际改动。每条记录注明证据来自合成验收、真实试用还是项目负责人自测。

| 案例 | 失败表现与原因 | 产品决策 | 如何验证 |
| --- | --- | --- | --- |
| 简历经历归错类 | 合成基线中，项目摘要被分到其他经历。真实试用还出现把实习放进项目的情况。抽取时缺少稳定的章节定位。 | 先在本地识别原文标题和经历，保留正文和引用，再核对模型归类。 | 试用原文件在本地复查实习与项目分组。合成回归覆盖把实习正文误分到项目的情况。[合成基线](../AI_EVALUATION.md#人工复核与改进线索) · [首轮试用](USER_TRIAL_RECAP.md) · [测试](../../backend/tests/test_resumes.py) |
| PDF 中文显示正常，解析文字乱码 | 一份试用 PDF 缺少可用的 Unicode 映射，原始文本无法用于匹配。 | 对符合条件的 Adobe-GB1 横排 PDF 本地补充标准字符映射。 | 原试用文件的两页中文恢复可读。合成测试单独覆盖缺少 `ToUnicode` 的情况。[试用复盘](USER_TRIAL_RECAP.md) · [测试](../../backend/tests/test_resumes.py) |
| 新增证据后分数反而下降 | 合成演示里，旧分母只含已有证据的要求，新证据低于原平均值时会把总分拉低。 | 固定同一 JD 的计分口径，把缺证项目保留在分母里并暂计 0 分。 | 合成简历补写一条 PRD 原文后，在 `v6` 规则下从 15.00 分升至 30.63 分。数据分析项仍待核实。[前后截图和合成样本](DEMO_RESUME_REMATCH.md) · [测试](../../backend/tests/test_jobs.py) |
| 改了简历，两版仍然同分 | 个人实测中，`v9` 能读到新的工具使用说明，但没有继续判断使用频率和改进案例，也漏掉了其他新增证据。 | 将频率、实际任务和改进验证纳入工具条款。用具体体验问题及交互调整支持用户体验条款。 | 同一 JD、同一 `v10` 规则下，原版本地复算 33.21 分，新版实际页面报告 76.09 分。回归覆盖有具体案例、只提工具名和明确缺证等情形。[个人实测](PERSONAL_RESUME_REMATCH.md) · [测试](../../backend/tests/test_jobs.py) |
