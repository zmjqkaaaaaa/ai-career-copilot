## 1. 20 分钟模拟

| 用时 | 面试环节 | 自测要求 |
| --- | --- | --- |
| 2 分钟 | 项目介绍 | 交代目标用户、真实痛点、本人决策及当前证据。 |
| 5 分钟 | 产品问题和方案 | 用一条 JD 解释最小任务，并说明为何没有把首轮试用做成完整求职流程。 |
| 6 分钟 | AI 与工程追问 | 说出模型、Python、证据和失败是怎样衔接的。 |
| 4 分钟 | 指标与迭代 | 对照 12/12 结构和 9/12 业务，说明下一轮怎么验证。 |
| 3 分钟 | 个人贡献与复盘 | 分清个人决策、协作实现和待确认事项。 |

## 2. 60 秒开场参考

我在准备 AI 产品实习时，发现有项目经历并不代表简历能证明岗位需要的能力。我做这个项目，希望学生能拿一份简历和目标 JD 找出先做什么。我确定的最小任务是看报告后改一处真实经历，再用同一 JD 复查。产品把 JD 原句、简历证据和优先差距放在同一份报告里，模型提取候选要求，Python 在用户确认后做可复算匹配。后续还能用相同资料做项目练习和模拟面试。我负责产品方向、任务和指标的定义，代码通过 Codex 协作实现。合成账号验证了模块之间的数据链，真实用户能否完成 48 小时复查仍待试用。

## 3. 项目深挖题库

先独立回答左栏，再用右栏的证据核对。具体代码考查见 [技术题库](CODE_INTERVIEW_QUESTIONS.md)。

| 题目 | 合格回答应包含 |
| --- | --- |
| 1. 为什么起点是一条 JD？ | 本人的真实卡点；已有经历与目标要求如何对应；如何以同一输入验证变化。 |
| 2. 你凭什么判断这是其他学生的问题？ | 明确只有本人复盘及一个同学个案；提出招募对象与最近一次投递的非引导式追问。 |
| 3. 如果有人没做过项目，他是不是首要用户？ | 说明第一批有经历和 JD 的用户为何便于检验诊断；零基础的起步路径是另一个场景。 |
| 4. 为什么不只做简历改写？ | 按差距的性质区分表达可补和实际能力待练；用一项 JD 要求举例。 |
| 5. 你怎样判断竞品和自己的差异？ | 选同一任务和可比维度，把公开能力与体验验证区分；差异化是待证假设。 |
| 6. 如果时间只有一周，你会删掉哪个模块？ | 围绕确认、匹配、修改与复查保留最小路径；说明其他任务怎样以入口或人工代替。 |
| 7. 如何处理两条都显得很重要的差距？ | 有明确不可及时弥补的硬约束；把可补证据、可改表达和需长期练习的差距分开。 |
| 8. 产品用什么证据解释匹配结果？ | 来源简历版本与 JD 修订、要求原句、用户自述、已有证明及覆盖率。 |
| 9. 为什么让 Python 打分？ | 硬性条件、证据权重、缺值及可复算性；模型做抽取和可选建议。 |
| 10. JSON 格式正确，怎样判断可信？ | Pydantic、业务引用、证据支持含义及用户确认，提供一个合成反例。 |
| 11. 项目是否用了 Agent 或 RAG？ | 固定工作流与受控工具、代码按路径和符号检索、证据注入 Prompt；无自主工具调用和向量库。 |
| 12. 为什么异步任务要保留版本？ | 从用户确认到执行可能发生变化，用任务、输入、提供方及状态防止旧结果误写。 |
| 13. 模拟面试的动态追问怎样控制？ | 依据当前回答片段、阶段、预算和父题规则；报告区分评估范围。 |
| 14. 为什么代码讲解引用 Git SHA？ | HEAD 会变化；解释、测验与报告应能回查原提交及具体文件行。 |
| 15. 如果外部模型挂了，哪些操作还能做？ | 本地上传解析、已确认数据和规则匹配的边界；说明依赖服务的步骤如何失败、反馈或重试。 |
| 16. 9/12 能叫“模型准确率 75%”吗？ | 说成历史样本的业务检查通过率；每类一条；三类失败及改进测试。 |
| 17. 离线跑 12/12 通过说明什么？ | 固定正确、错误和损坏输出的评测规则行为；与真实模型调用区别。 |
| 18. 120 项通过为何不能证明产品有价值？ | 受控合成账号、测试库和浏览器验证功能；真人任务、成本和阻塞点需要独立观察。 |
| 19. 48 小时指标分子和分母如何设？ | 从首次读完报告起跟踪；有表达可改善的差距、观察窗结束；真实修改、同 JD 复查及可复述变化。 |
| 20. 试点中完成率低，先做什么？ | 查看阻塞：差距难理解、修订成本高或找不到复查；按证据决定测试改动。 |
| 21. 这部分代码是你自己写的吗？ | 诚实说明 Codex 协作。具体讲你决定了什么、如何验收、哪些能沿代码独立说明。 |
| 22. 哪个判断可能被推翻？ | 选一项明确假设，说明观察结果怎样支持或推翻首轮定位。 |
| 23. 对 AI Agent 产品岗位，你想展示什么？ | 任务分解、工具和数据权限、状态、回退、评测。当任务需要动态计划时先做对照，再决定是否引入。 |
| 24. 对智能硬件或 AI 应用岗位，你会怎么讲这段经历？ | 用具体用户场景、信息采集、约束、评价和迭代迁移思路，避免代入未接触的企业内部业务。 |
