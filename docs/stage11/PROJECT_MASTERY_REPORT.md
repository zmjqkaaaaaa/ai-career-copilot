## 1. 100 分评分标准

评分人先按每个观察点给 0–5。0 表示没有回答，1 表示核心有误，2 表示概念正确但泛化，3 表示能结合项目说明，4 表示能给准确证据并应对追问，5 表示能进一步说明取舍、例外和验证。单项得分为“等级 ÷ 5 × 权重”，各项相加得到总分。未完成的部分标待测，评分结果注明已测范围和用时。

## 3. 独立练习模式

1. **第一轮 20 分钟。** 1 分钟项目介绍后，独立答 P05、P11、A09、T16、D16、C08。每题约 90 秒，剩余时间模拟两个追问。
2. **第二轮 30 分钟。** 任选一条核心链路，关闭手册后定位前端、API、Service、表和测试。用一条失败输入口述降级路线，再对照 [代码清单](CODE_REFERENCE_MAP.md)。
3. **第三轮按岗位练。** AI 产品重做 P08 和 D10；Agent 岗位做 A07、A08 和 C03；AI 应用与数字化产品做 C08、C09 和 C15。企业示例均作为产品设计题。
4. 先录音或写答案，再打开 [参考答案](INTERVIEW_ANSWERS.md)。挑两条可核实的错误，依据源码或报告修正后复答。

## 4. 主要失分点和下一轮计划

下列是依据项目复杂度预设的风险，不属于个人实测结果。实际失分点、答题证据和改进效果需在口述后填写。

| 可能失分点 | 发现信号 | 改进练习 |
| --- | --- | --- |
| 模型与规则边界混淆 | 将匹配分或最终追问完全归给模型 | 在 90 秒内对比 JD 抽取、Python 评分和确认步骤，再举一个硬门槛例子 |
| 对验证数字过度概括 | 把 9/12 称为通用准确率，或把合成系统验收说成真人价值 | 按数据集、分母、评估目标和适用范围四项重述 |
| 只讲技术名词 | 说不清见哪个路由、用哪一版资料 | 补一条 API、一个函数、一张表、一个测试 |
| 个人贡献和协作混在一起 | 无法指出自己做过的产品决策或证据 | 用“我选择的范围或指标”举例，同时明确 Codex 协作 |
| 缺少产品迭代条件 | 只说加功能、再用大模型 | 给可观察阻塞、一个改动、一个能推翻假设的结果 |

**下一轮优先验证**：先录制 1 分钟项目介绍，然后回答 P11、T16 和 D16。达到能独立说出指标分母、规则与模型边界、以及两种评测差异后，再进行完整模拟。当前无本人分数或通过记录。
