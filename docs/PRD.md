# 产品需求文档

## 产品目标

帮助缺少 AI 产品实习和项目经验的学生完成职业定位、项目选择、项目理解和面试准备，逐步积累能够独立解释和展示的求职成果。

## 第一阶段范围

- 搭建桌面与平板可用的共享导航、顶部栏和主内容区。
- 驾驶舱呈现欢迎区、求职概览、五个核心能力入口、六项演示能力、四项演示任务及成长路径。
- 用户能从导航、搜索或驾驶舱卡片进入模块。模块页展示「待开发」、模块说明和后续计划。
- 演示任务可切换完成状态，刷新后从浏览器本地存储恢复。
- 搜索匹配本地模块，通知使用空状态，头像进入个人档案占位页。

## 第一阶段验收

直接访问和刷新子页面时，标题、面包屑、导航高亮一致。示例概览与能力分数有明确标记。常见平板宽度可以打开菜单并切换页面，驾驶舱无需横向滚动。

## 第二阶段范围

- 用户可注册、登录、退出，并在有效会话内刷新恢复。个人档案页需要登录。
- 用户可保存教育信息、毕业年份、目标岗位、兴趣行业、技能、实习和项目经历。每个用户只读写自己的档案。
- 驾驶舱展示真实用户名、目标岗位和档案状态。求职阶段、项目数量、能力图、演示任务和成长路径继续有示例标记。
- 后端提供 MySQL、Alembic、JWT、密码哈希和输入校验。浏览器使用受 CSRF 校验的短时 HttpOnly Cookie。

## 第三阶段范围

- 登录用户上传、管理和删除自己的 PDF 或 DOCX 简历，主动发起本地解析。
- 核对脱敏预览后发起模型提取，修正并确认结构化条目。
- 根据目标方向生成可回溯的职业报告，查看能力证据状态和历史报告。
- 核对简历优化前后对比，确认后保存单独的文本版本。

## 第四阶段范围

- 录入岗位、粘贴或导入 JD、核对模型提取的职责和要求。
- 选定已确认的简历版本，计算可复算的参考分和证据覆盖率。
- 查看硬性要求、待验证和差距，生成投递准备建议，管理历史记录。

## 第五阶段范围

- 从亲历事件探索兴趣，确认推断，形成有来源的痛点、访谈问题和验证计划。
- 查询或补录公开资料，核对竞品事实；记录证据、机会分和覆盖率。
- 比较至少三个项目方向，收藏、编辑和选定，生成并管理带验收标准的 PRD 版本。

## 第六阶段范围

- 导入公开 GitHub 仓库，按提交读取文件树、入口、依赖和静态符号。
- 根据当前版本已读代码完成架构分析、代码解释、知识检索与导师问答。
- 完成代码理解测试，按评分点查看反馈和分版本掌握报告。

## 第七阶段范围

- 复用用户档案和已确认资料，配置五种文字面试模式、时间、难度、风格和提示。
- 逐题模拟、从作答动态追问并恢复进度，按题型和引用证据评估。
- 提供面试报告、历史、训练任务和进度。

## 第八阶段范围

- 汇总岗位、简历、项目与面试证据，生成带先修与预算的学习路线。
- 安排任务，保存教学会话和资料，提交实践作业并根据证据复习。
- 通过阶段测评记录能力升降，按历史证据展示学习进度。
- 登录后驾驶舱显示本人能力证据的状态统计。求职阶段、完成项目数和演示任务继续使用已有示例口径。

## 跨阶段使用流程

- 选定推荐方案后可在项目工作台关联公开仓库。仓库的公开可读性仅用于代码练习，关联记录本身不证明作者或个人贡献。
- 从项目工作台选择具体提交进入项目面试时，自动填充仓库与提交。已关联的方案及其最新 PRD 默认进入本次准备，创建会话后保存当时的版本。

## 第九阶段范围

- 在求职执行工作台管理用户保存的岗位、收藏和确认的简历版本，使用现有岗位匹配。
- 保存投递、状态历史和真实面试日程，从该投递保留的 JD 和简历版本进入模拟面试。
- 按投递日期查看统计及分组结果，样本不足时展示计数，用户确认后可生成匿名 AI 策略。
- 招聘岗位来源为用户输入的真实信息或链接。用户在招聘渠道完成投递和联系。
