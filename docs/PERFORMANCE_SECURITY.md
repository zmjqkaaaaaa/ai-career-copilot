# 第十阶段 Sprint 5 · 性能、安全与模型用量

## 查询基线和结果

在隔离 MySQL 测试库使用生成的岗位、投递、状态历史和面试日程。FastAPI 在本机进程内运行。每个接口每档预热后测量 20 次，并发 4。数据量为 0、250、1,000 条投递。优化前看板读取全量，优化后模拟前端每列先取 30 条。统计接口保留同一请求参数。两次运行的每档汇总计数和比率一致。

| 场景 | 优化前 P95 | 优化后 P95 | 优化前响应 | 优化后响应 |
| --- | ---: | ---: | ---: | ---: |
| 250 条 · 投递看板 | 203.05 ms | 99.03 ms | 77,999 B | 39,672 B |
| 1,000 条 · 投递看板 | 648.44 ms | 99.64 ms | 312,579 B | 39,672 B |
| 250 条 · 求职统计 | 115.67 ms | 73.03 ms | 7,819 B | 7,819 B |
| 1,000 条 · 求职统计 | 468.15 ms | 172.22 ms | 7,871 B | 7,871 B |
| 空库 · 投递看板 | 25.14 ms | 43.76 ms | 178 B | 385 B |

概览只读取部分最近记录和待办。进入看板时不读统计，切换统计时不加载看板和简历版本。看板用最后一条记录的更新时间和编号请求下一页。同一秒更新的记录仍有稳定次序，已取到的数据可继续拖动。SQL 使用用户、状态、时间和编号组合索引；统计只取汇总需要的列和去重后的结果，避免读取整个 JD 快照。空数据分页增加了计数与提示字段，响应存在额外开销。旧客户端仍可用原有完整看板接口，日程选择器继续兼容原行为。以上时延不代表公网首屏时延。

## 队列和模型

隔离的本机队列实验使用一个固定 300 ms 的慢任务和一个短任务，重复 5 次。短任务从排队到开始的中位时间，串行基线为 300.37 ms，两路调度为 0.50 ms。实验只测调度行为。真实任务还受 MySQL、进程竞争和第三方服务限额影响。

共享 Worker 使用默认 2 路、可配置为 1–4 路的有界执行。每个进程内同类型工作流同时最多执行一个调度项。MySQL 的任务认领、超时恢复及版本校验仍由原各模块负责。这避免单个等待模型的任务占满整个 Worker。简历解析任务和匹配结果继续使用现有去重键，在原有权限范围重用。求职策略同一失败任务最多执行三次。

真实模型验证通过单次显式批准的合成测试运行。阿里云百炼 `deepseek-v4.1-flash` 返回 735 输入 Token、349 输出 Token，Provider 计时 2,334 ms，成功写入隔离库。没有配置价格，因此该调用的估算费用为空。独立的虚构价格测试用两次调用验证了公式：每次 1,000 输入 Token 和 500 输出 Token，以假设价 2 与 4 CNY／百万 Token 计算，每次估算 0.00400000 CNY，两次合计 0.00800000 CNY。

## 模型用量口径

`llm_call_metrics` 记录模块、内部用户 ID、任务编号、尝试次数、模型、提示词版本、状态、耗时和供应商返回的输入输出 Token。系统可以在首次尝试保存从入队到领取的等待时间。现有工作流对重试入队时刻有不同约定，重试等待时间暂留空。删账户时关联用量记录通过外键一并删除。

只有带业务任务上下文的 Provider 调用写用量记录。用量写入失败只记录错误类型，业务结果正常返回。模型返回格式未通过时，即使业务没有保存结果，供应商已返还的 Token 仍计入。业务后续校验的通过率与 Provider 状态分别理解。用量表不保存简历、提示载荷、回答、系统提示词、密钥或第三方地址。

费用使用 `LLM_PRICES` 中对应模型的输入、输出单价。报价单位是每百万 Token，按货币分组汇总。价格或 Token 缺失时保留空值，估算仅覆盖能定价的调用。结算还可能受折扣、缓存和供应商口径影响，应通过账单核对实际开支。

```powershell
# 在 backend 目录，连接你有权访问的环境后运行
& .venv/Scripts/python.exe -m app.services.llm_monitoring_service --group module
# group 支持 module、model、task、user、total，可用 --user-id 限定账号
```

## 安全审计与验证

| 项目 | 本轮检查与修复 | 上线前剩余验证 |
| --- | --- | --- |
| 登录和账户操作 | 生产模式使用 MySQL 共享限流。并发测试在两个限流对象间发起 12 次请求，严格通过 5 次，其余获 429。键保存为 HMAC 指纹，存储失败时认证操作返回 503。 | 部署后复核反向代理信任范围、出口地址归并行为和分布式限流。 |
| PDF 与上传 | 在 PDF 读取前为解压、综合解码、页面树设置限制，并限制外部解码依赖。保留现有文件大小与权限校验。测试验证超限映射和线程调用上下文恢复，普通 PDF/DOCX 流程参与回归。 | 在生产容器压测文件资源上限、进程隔离与代理请求体限制。 |
| 权限、会话与删除 | 测试复核分页与统计仅返回当前用户数据。既有 CSRF、权限和账户删除回归继续运行，用量记录随账户删除覆盖。API 加入 `nosniff`，数据库错误日志隐藏 SQL 参数。 | 验证 HTTPS、Cookie 生产行为、备份清除、访问日志与告警。 |
| 模型数据边界 | 真实调用仅发送内置合成数据。用量记录只存安全元数据。保留已审核的预览签名、Provider 允许主机与证据校验。 | 对生产日志和第三方配置做实际部署复核。 |
