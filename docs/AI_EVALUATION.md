## 人工复核与改进线索

1. 简历样本注明「参与整理库存看板的数据需求」，预期归入项目经历。模型保留了事实，但放进「其他经历」。原句未写明项目栏目，分类有解释空间。增加带明确项目段落和弱线索段落的成对样本，分别报告召回率和分类结果。
2. 简历优化如实保留了「参与」边界，项目建议仅提供补证提示。对于已知事实，仍可给出保持原意的保守改写。后续把「无捏造」和「有可采用表达」设成两项单独指标。
3. 面试问题问如何统计不同岗位的数量，回答已指出按岗位 ID 去重再计数。模型因缺少具体 SQL、关联成因和分类统计方案而扣分。补充概念题与实现题对照，明确只有问到写法或分类统计时才评价这些细节。

固定答案和自动规则负责核对字段、原文、边界和可复算结果。关键词规则覆盖预设风险，无法检验每种改写是否真实。首次人工复查了三个未通过输出。可选评审模型输出是辅助意见，本轮未启用。没有用模型自评替代本轮证据。

## Prompt Registry

已登记 22 个生产提示词，按简历、岗位匹配、探索、市场研究、代码、面试、学习、求职策略分类。每条记录可导出提示词指令、示例、最低输入变量契约、现有 Pydantic 输出结构和模型配置来源。原始创建时间缺乏可核实记录，分别保留空的 `created_at` 和首次登记日期。锁文件中的摘要检验提示词与契约内容。同一版本内容直接发生变更时，评估及测试会报错。

候选版本应作为独立定义连同元数据加入 Registry，并保留既有版本的提示词与结构。通过 `--prompt-version 名称=版本` 可在评估中选择旧版或候选版，不改业务任务使用的版本。在相同数据版本、样本和运行模式下用 `--compare` 对比逐检查项差异。需要回滚已发布提示词时，先选定已验收的历史版本，按 Git 发布流程恢复对应生产定义。任务已有签名和版本指纹，用这些机制避免在后台静默替换模型提示。当前每个提示词只有一个实际登记版本，自动化用第二个**测试版本**验证了历史选择和未登记改动拒绝。
